# tools/eval — стенд агентного оценочного набора (R2.2, задача N3)

Стенд прогоняет набор задач через любой OpenAI-совместимый сервер (llama.cpp, ik_llama.cpp, vLLM, SGLang, TabbyAPI,
Strata — если он совместим), сам проверяет ответы и пишет каталог прогона. Два прогона сравниваются попарно по задачам
(`compare.py`): например, «UD-Q4_K_XL против эталонного кванта» или «движок A против движка B».

**Статус.** Проверен только на скриптовом мок-сервере в `tests/test_eval.py` (CONFIRMED: литеральный вывод в
`docs/evidence/2026-10-10-eval-stand.md`). Против реальных движков — **NOT RUN**. Синтетический набор
`tasks-synthetic/` проверяет стенд и служит шаблоном; о качестве модели он ничего не говорит.

Только Python 3 и stdlib (проверено на 3.13.16 — CONFIRMED, `python3 --version` в evidence), без pip и без интернета.
Песочница для кода — Linux (`unshare` из util-linux и Landlock в ядре; см. раздел 6).

## 2. Команды

```bash
# 1) проверить набор задач без сервера: формат, пути, эталонные ответы проходят, фикстуры без правки падают
python3 tools/eval/run_eval.py --tasks <DIR> --validate-only

# 2) прогон (температура 0 по умолчанию; повторы — для оценки разброса)
python3 tools/eval/run_eval.py --url http://127.0.0.1:<PORT> --tasks <DIR> --out docs/evidence/R2-eval/<дата>-<движок>-<квант> \
  --repeats 3 --temperature 0 --max-tokens 4096 \
  --engine-desc "<движок @ commit; команда сервера>" --model-desc "<модель, квант, файлы>"

# 3) сравнение двух прогонов одного набора
python3 tools/eval/compare.py <RUN_A> <RUN_B> --json <RUN_A>/compare-vs-B.json
```

Полезные ключи `run_eval.py`: `--only code_fix,SYNTHETIC-tool_use-*` (категории, id, glob), `--stream off` (обычный JSON
вместо SSE — если у движка ломаются потоковые tool calls), `--extra-body '{"chat_template_kwargs": {"enable_thinking": false}}'`,
`--seed N`, `--model ID`, `--timeout`, `--total-timeout`, `--aggregate majority|all|any|first`, `--weak-sandbox`,
`--keep-workdirs`, `--raw-prompt-chars N` (0 — хранить промпты целиком).

Код выхода: 0 — прогон завершён без ошибок запросов и стенда; 1 — завершён, но есть `request_error`/`harness_error`;
2 — фатально (неверный набор задач, нет id модели); 130 — прерван. Доля решённых на код выхода не влияет.

## 3. Формат задачи

Одна задача — один файл `*.task.json` (UTF-8, обычный JSON) в каталоге набора или в его подкаталогах. Каталоги,
имя которых начинается с `.` или `_`, пропускаются. Все пути в задаче — относительно файла задачи и не могут
выходить за каталог набора (проверяется после разрешения символических ссылок). Лишние поля — ошибка (ловит опечатки).

| поле | обязательно | смысл |
|---|---|---|
| `id` | да | `[A-Za-z0-9][A-Za-z0-9_.-]{0,127}`, уникален в наборе |
| `category` | да | `code_fix`, `code_write`, `tool_use`, `long_doc_qa`, `structured_output`, `reasoning` |
| `messages` | да | `[{"role": "system"\|"user"\|"assistant", "content": "..."}]`, последнее — `user` |
| `check` | да | правило проверки, своё для категории (ниже) |
| `fixture` | code_* | каталог с маленьким репозиторием и тестами |
| `document` | нет | `{"file": "docs/x.txt"}` или `{"text": "..."}` — подставляется в `{{document}}` |
| `tools`, `tool_simulator`, `max_turns` | tool_use | схемы функций OpenAI; симулятор; лимит ходов (по умолчанию 8, максимум 50) |
| `max_tokens` | нет | переопределяет `--max-tokens` для этой задачи |
| `response_format`, `tool_choice` | нет | передаются в запрос как есть |
| `reference_answer` | нет | эталонный ответ (строка или `{"file": ...}`); нужен `--validate-only`, модели не показывается |
| `synthetic`, `description`, `notes`, `tags` | нет | описание; `synthetic: true` — задача не является доказательством |

Подстановки в `content` (выполняются один раз; вставленный текст повторно не разбирается; прочие `{{...}}` остаются как есть):
`{{document}}`, `{{file:<путь в фикстуре>}}`, `{{fixture_tree}}` (список файлов фикстуры), `{{answer_protocol}}` (текст
протокола ответа из раздела 4).

Хэш задачи (`sha256`) считается по JSON задачи и по содержимому всех файлов, на которые она ссылается (фикстура,
overlay, документ, эталон). `compare.py` сравнивает задачи только с одинаковым хэшем.

### Проверки (`check`) по категориям

**code_fix / code_write** — `{"type": "code_tests", "command": [...]}`:
- `command` — argv без shell; `{python}` заменяется на интерпретатор стенда. Рабочий каталог — копия фикстуры.
- `timeout_s` (по умолчанию 60), `limits` `{as_mb, fsize_mb, nofile, nproc}` (по умолчанию 2048 / 64 / 256 / не задан; 0 — без лимита),
  `env` — дополнительные переменные окружения теста.
- `protected_paths` — glob-шаблоны (fnmatch, `*` захватывает и `/`), которые ответ не может создавать/менять/удалять.
  По умолчанию: `test_*.py`, `*/test_*.py`, `*_test.py`, `tests/*`, `*/tests/*`, `test/*`, `*/test/*`, `conftest.py`, `*/conftest.py`.
- `allowed_paths` — если задано, ответ может менять только эти пути.
- `overlay` — каталог, который копируется поверх рабочей копии ПОСЛЕ применения ответа (скрытые тесты).
- `expect_fixture_fails` (по умолчанию `true`) — `--validate-only` требует, чтобы тесты на нетронутой фикстуре падали.
- PASS = ответ применился, тесты завершились с кодом 0 до таймаута. Таймаут — FAIL с причиной `timeout`.

**tool_use** — `{"type": "tool_use", ...}`:
- `required_calls`: `[{"name", "arguments"?, "match"?: "subset"(по умолчанию)|"exact"}]` — каждый обязательный вызов
  должен совпасть с отдельным фактическим вызовом; без `arguments` проверяется только имя.
- `order`: `strict` (по умолчанию: обязательные вызовы встречаются именно в этом порядке, между ними могут быть другие) или `any`.
- `forbidden_calls` (тот же формат), `max_calls`, `require_valid_arguments` (по умолчанию `true`: все аргументы — JSON-объекты),
  `final_answer` — правило сопоставления текста (как у long_doc_qa) для итогового ответа.
- Ход = один запрос к модели. Если модель вызывает инструменты, стенд исполняет их через симулятор, добавляет
  сообщения `assistant` (с `tool_calls`) и `tool` (с `tool_call_id`) и делает следующий ход. Итог — первый ответ без
  вызовов. Если за `max_turns` ходов итога нет — FAIL «turn limit reached».
- Балл = доля пройденных подпроверок; PASS = пройдены все.

`tool_simulator` содержит только данные, никакого кода:
```json
{"responses": [{"name": "get_order", "arguments": {"order_id": "A-1027"}, "match": "exact", "result": {"status": "delivered"}},
               {"name": "poll", "arguments": {}, "match": "subset", "results": ["pending", "done"]}],
 "builtins": {"calculator": {"impl": "calculator"},
              "get_stock": {"impl": "lookup", "key_arg": "sku", "table": {"KB-200": {"units": 140}}},
              "search_kb": {"impl": "search", "query_arg": "query", "documents": [{"id": "d1", "text": "..."}]}},
 "default_result": {"error": "..."}}
```
Сначала ищется заготовленный ответ (первое совпадение по имени и аргументам; `exact` — равенство JSON, где 12.5 = 12.50,
но `"12.5"` ≠ 12.5; `subset` — заданные ключи совпадают, лишние разрешены; `results` — последовательные ответы на повторные
вызовы), затем встроенная функция стенда (`calculator` — только арифметика через AST, `lookup` — таблица из задачи,
`search` — поиск подстрок по документам задачи), иначе `default_result`. Неизвестный инструмент и невалидный JSON
аргументов возвращают модели ошибку и отмечаются в проверке.

**long_doc_qa** и **reasoning** — правило сопоставления текста:
- `type`: `exact` (`answers`: строка совпадает после обрезки пробелов), `normalized` (`answers`; NFKC, без регистра,
  без `**`/`` ` ``/кавычек вокруг и `. , ; : !` в конце, пробелы схлопнуты), `regex` (`pattern`, `flags` из `ims`,
  `fullmatch`), `contains_all` / `contains_any` (`values`, после нормализации), `number` (`value`, `abs_tol`, `rel_tol`).
  Для reasoning допустимы только `exact`, `normalized`, `number`.
- `extract`: `whole` (весь ответ), `answer_line` (текст после ПОСЛЕДНЕЙ строки `ANSWER:` / `Answer:` / `Final answer:` /
  `Ответ:` / `Итоговый ответ:`, жирный markdown допускается; ответ должен быть в той же строке), `last_line`, `regex`
  (`extract_regex`, группа 1).
- `number`: берётся первое число; группы по 3 цифры через пробел/NBSP/`_`/`'` склеиваются; десятичная запятая
  допускается (`1,5` = 1.5), но `1,234` читается как 1234 (тысячи), `1,234.5` = 1234.5. Неоднозначных ответов лучше избегать.
- Проверяется только `content`. Рассуждение (`reasoning_content`) не оценивается; если в `content` есть `</think>`,
  оценивается только текст после последнего `</think>`.

**structured_output** — `{"type": "json_schema", "schema": {...}, "values": [...], "parse": "strict"|"lenient"}`:
- `parse: strict` — весь ответ должен быть одним JSON-значением; `lenient` — допускается блок ```` ```json ```` или
  фрагмент от первой `{`/`[` до последней `}`/`]`.
- Подмножество JSON Schema (`ev_schema.py`): `type`, `enum`, `const`, `properties`, `required`, `additionalProperties`,
  `minProperties`/`maxProperties`, `items` (одна схема), `minItems`/`maxItems`/`uniqueItems`, `minLength`/`maxLength`/`pattern`,
  `minimum`/`maximum`/`exclusiveMinimum`/`exclusiveMaximum`/`multipleOf`, `allOf`/`anyOf`/`oneOf`/`not`, локальный `$ref`.
  `format` и описательные поля принимаются, но не проверяются. Любое другое ключевое слово — ошибка набора (а не молчаливый пропуск).
  `true`/`false` не являются числами; `1.0` — целое.
- `values`: `[{"path": "/items/0/sku", <одна операция>}]`, путь — JSON Pointer; операции `equals`, `approx` (+`tol`),
  `regex`, `one_of`, `length`, `exists`.
- Балл = доля подпроверок (схема + каждое значение); PASS = все.

Примеры всех категорий — в `tasks-synthetic/`.

## 4. Протокол ответа для code-задач

Текст, который модель получает через `{{answer_protocol}}` (`ev_patch.ANSWER_PROTOCOL`):
```
Answer format (machine-checked; prose outside these blocks is ignored):
- To create or replace a file, write a line `FILE: <path relative to the repository root>` and, right after it, a fenced code block with the COMPLETE new content of that file.
- Or give a unified diff in a ```diff fenced block with `--- a/<path>` and `+++ b/<path>` headers and @@ hunks.
- To delete a file, write a line `DELETE: <path>`.
- Do not modify the tests.
```
Точные правила применения:
1. Блок файла: строка `FILE: путь` (регистр слова не важен; допускаются `### FILE: путь`, `**FILE: путь**`, путь в
   обратных кавычках), затем, возможно после пустых строк, огороженный блок ```` ``` ```` или `~~~` с любым языком.
   Содержимое блока — новый файл целиком. Закрывающая ограда — не короче открывающей (файл с ```` ``` ```` внутри
   оборачивается в ```` ```` ````). `DELETE: путь` удаляет файл.
2. Unified diff: блоки ```` ```diff ```` / ```` ```patch ````; если их нет и нет блоков FILE — ищется голый diff в тексте.
   Префиксы `a/` и `b/` снимаются, когда они есть у обоих заголовков; `/dev/null` — создание/удаление.
   Числа строк в `@@` не обязательны и не проверяются (как `git apply --recount`); контекст и удаляемые строки должны
   совпасть с файлом (без учёта пробелов в конце строки); поиск — от номера строки из заголовка в обе стороны, но не
   раньше конца предыдущего ханка; пустая строка внутри ханка — пустая строка контекста; `\ No newline at end of file` учитывается.
3. Если в ответе есть хоть один `FILE:`/`DELETE:`, применяются только они, diff-блоки игнорируются (это пишется в `notes`).
4. Пути: только относительные, без `..`, NUL и `\`; запрещена запись через символическую ссылку и в каталог, который
   разрешается за пределы рабочей копии; защищённые и неразрешённые пути (раздел 3) — FAIL.
5. Ответ, в котором нет ни блока файла, ни diff, — FAIL «no FILE: block or unified diff found» (это ошибка модели, не стенда).

## 5. Статусы, файлы прогона, статистика

`results.jsonl` — одна строка на задачу × повтор: `status`, `pass`, `score`, `reason`, `details` (для кода — применённые
правки, diff, хвосты stdout/stderr, код возврата, фактическая изоляция; для инструментов — все вызовы и подпроверки),
`n_requests`, `usage`, `finish_reason`, `truncated`, `task_sha256`, `raw_seqs` (ссылки на строки `raw.jsonl`).

| status | что значит | входит в долю решённых |
|---|---|---|
| `pass` / `fail` | модель решила / не решила (включая неверный формат, таймаут тестов, лимит ходов) | да |
| `request_error` | запрос не удался: сеть, HTTP-ошибка, оборванный поток, ответ без `choices`/`finish_reason` | **нет**, считается отдельно |
| `harness_error` | стенд не смог проверить (нет песочницы, исключение в стенде) | **нет**, считается отдельно |

Ответ, оборванный по `max_tokens` (`finish_reason: length`), — это `fail` с пометкой `truncated` (у всех кандидатов одинаковый лимит).

`raw.jsonl` — каждый запрос (сообщения; содержимое длиннее `--raw-prompt-chars` хранится как начало/конец + sha256),
ответ целиком, тайминги потока и `usage` (метрики `tools/bench/runlog.request_metrics`), каждое исполнение инструмента,
каждый запуск песочницы, итог задачи. `meta.json` — как у `tools/bench` (`is_mock_server`, git SHA, хост, `/v1/models`,
описания движка и модели) плюс блок `eval`: id и хэши задач, хэш набора, параметры, возможности песочницы.

`summary.json` по каждой категории и в целом:
- `task_pass_rate` и `task_ci95` — по задачам: повторы задачи сворачиваются в один исход правилом `--aggregate`
  (`majority`: больше половины валидных повторов прошли; ничья — FAIL); знаменатель — задачи с хотя бы одним валидным повтором;
  интервал Уилсона 95% (z = 1.959964).
- `attempt_pass_rate` и `attempt_ci95` — по попыткам (задача × повтор); при повторах > 1 интервал занижен, потому что
  повторы одной задачи не независимы. Для решений использовать уровень задач.
- `n_request_errors`, `n_harness_errors`, `n_truncated`, `tasks_failed`, `tasks_without_valid_attempt`, `mean_score`
  (частичный балл, справочно). Прогон на мок-сервере помечается `MOCK SERVER RUN`, синтетический набор — `SYNTHETIC TASK SET`.

`compare.py`: единица — задача; пара — задача с валидным исходом в обоих прогонах и одинаковым `task_sha256`
(остальные перечисляются как исключённые). b = прошла только в A, c = только в B. Точный двусторонний тест Мак-Немара
использует только b и c: p = min(1, 2·P[Bin(b+c, ½) ≤ min(b, c)]). Разность долей A − B = (b − c)/n, 95% интервал —
перцентильный бутстреп по задачам с одинаковыми выборками для A и B (10 000 повторов, seed 0). При b + c < 6 тест не может
дать p < 0.05 (помечается `low power`). Предупреждения: мок, синтетика, разные температура/лимит/набор/повторы/seed/extra_body.

## 6. Песочница для code-задач

Каждая попытка: свежая копия фикстуры во временном каталоге, применение ответа, overlay, запуск `command` через
`sandbox_exec.py`. Слои (фактически применённые записываются в `details.run.isolation` каждой попытки):

| слой | как | что даёт |
|---|---|---|
| сеть | `unshare --net --pid --fork --kill-child` (для не-root — с `--user --map-root-user`; запасные формы без PID namespace) | новый сетевой namespace: только выключенный loopback, нет доступа и к серверу модели на localhost |
| сеть (дубль) | Landlock ABI ≥ 4 (Linux ≥ 6.7): запрет TCP bind/connect | работает без namespace; UDP не закрывает |
| сеть (мягкий) | `sandbox_guard/sitecustomize.py` для Python-команд | запрет connect/sendto IPv4/IPv6 из Python; обходится подпроцессом — не граница безопасности |
| файлы | Landlock (Linux ≥ 5.13, без root): запись, создание, удаление, переименование — только внутри каталога попытки и `/dev/null` | тест не может испортить файлы вне временного каталога; **чтение не ограничено** |
| ресурсы | `RLIMIT_CPU` (таймаут + 5 с), `RLIMIT_AS`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`, `RLIMIT_CORE`=0, `PR_SET_NO_NEW_PRIVS` | защита от бесконечного счёта, памяти, огромных файлов |
| время | таймаут по стенным часам: kill всей группы процессов (и PID namespace) | зависший тест — FAIL `timeout` |
| окружение | собирается заново: `PATH` стенда, `HOME`/`TMPDIR` внутри попытки, `C.UTF-8`, `PYTHONHASHSEED=0` | ключи API и прочие переменные стенда в тест не попадают |

Политика по умолчанию: тесты запускаются, только если есть И сетевая изоляция (namespace или Landlock TCP), И
файловая (Landlock). Иначе попытка — `harness_error` с причиной (не провал модели). `--weak-sandbox` запускает с тем, что есть,
и пишет это в `meta.eval.sandbox_missing` и в каждую попытку. На машине разработки (ядро 6.18, root) доступны все слои —
CONFIRMED тестами `Sandbox.*` (evidence). На сервере заказчика — UNKNOWN до первого `--validate-only` (он печатает причину, если
слоя нет).

Что песочница НЕ делает: не ограничивает чтение файлов (интерпретатор и библиотеки должны читаться; задачи с секретами в
доступных для чтения местах на этой машине запускать нельзя), не закрывает UDP при отсутствии namespace, не изолирует
`/dev/shm` и IPC, не ограничивает число процессов (только по `limits.nproc`, он действует на всего пользователя).
Это защита от случайного и неаккуратного кода модели, а не от целенаправленного взлома ядра.

## 7. Ограничения и что не проверено

- Против реальных движков **NOT RUN**: формат потоковых tool calls, `response_format`, обработка `role: tool` у
  llama.cpp/vLLM/SGLang/Strata через этот стенд не проверялись. При проблемах с потоковыми tool calls — `--stream off`.
- Оценивается только машинно проверяемое. Качество текста, стиль, полнота объяснений (часть D из `R2-EVAL-SET.md`)
  оцениваются людьми вне стенда.
- Синтетические задачи короткие (документы ~3–5 КБ). Длинные документы 32K–262K токенов поддерживаются форматом
  (`document.file`), но на таких длинах стенд не запускался — NOT RUN.
- Пороговые значения лимитов песочницы (2 ГБ памяти, 64 МБ на файл, 256 дескрипторов) — PROVISIONAL, выбраны для
  маленьких Python-репозиториев; для тяжёлых тестов (сборка, JVM, Node) задаются в `check.limits` (0 — без лимита).
- Номера системных вызовов Landlock 444–446 общие для x86_64 и aarch64 (generic syscall table) — PROVISIONAL по
  документации ядра; проверено запуском только на x86_64 этой машины.
