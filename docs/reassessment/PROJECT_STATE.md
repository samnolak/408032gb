## Главное (коротко, после ревью)
1. **Аудит:** своего GPU-кода нет; на целевом сервере ничего не запускалось; реальные замеры GLM-5.3-Flash есть только с чужого
   стенда 1×3090 + RAM: ik_llama.cpp UD-Q4_K_XL 15.0 tok/s и база A (strata-glm-3090, NVFP4-пак) 13.89 tok/s с `--cpu-share`,
   повтор эксперта от предыдущего токена 24.6% (PROVISIONAL/REPORTED); цифры strata-glm 19.65 tok/s — синтетика; требования 262K и
   ≥4 бит в старом плане не учтены; P2P/NVMe/CPU — заявления.
2. **Физика (roofline, ред. 3, PROVISIONAL):** конвейер по слоям ≈ полоса одной карты. GLM-5.3-Flash UD-Q4_K_XL: конвейер без
   спекуляции ≤ ~42 tok/s при любом попадании; со спекуляцией (принятие 0.7) граница 50.6–52.9 — только с перекрытием CPU/GPU
   (Strata-подобный движок) и при попадании в кэш экспертов ≥ ~0.8, то есть при перекосе маршрутизации, которого никто не показал
   (база A: повтор эксперта 24.6%); без перекрытия (llama.cpp) ≤ ~47; при TP латент MLA реплицируется, TP@auto ≈ 41. **Без TP
   плотной части пол 50 tok/s при 262K для GLM — на пределе даже как граница, цель 80–100 недостижима.** Qwen3.8-Flash-Next (всё в
   VRAM): граница конвейера 84–87, со спекуляцией 95–101.
3. **Исследование:** **Qwen3.8-Flash-Next** — первый кандидат на замер, потому что его дешевле всего поднять (родная модель Strata,
   помещается в VRAM в UD-Q4_K_XL), а не «доказанно самый быстрый при 262K»: чужие замеры — 61.5–72.1 tok/s на 1×RTX PRO 4500
   (со спекуляцией MTP, KV int8, контекст ≤ 139K, 512 GB RAM) и 64–78 tok/s на 2×3090 (55 при промпте 128K; настройки KV и
   спекуляции в тексте не указаны) — на другом железе; llama.cpp на 6×4090 — 48.7 tok/s при 250K (REPORTED). Запасной лицензионно
   чистый кандидат того же класса — Qwen3.5-122B-A10B (Apache-2.0). **GLM-5.3-Flash** — лучшее качество среди помещающихся
   (AA 42 против 40, REPORTED), но см. п. 2. DeepSeek-V4.1-Flash в 4 битах не помещается (NVMe в активном пути).
4. **Решение (ADR-012 ред. 2, предварительное):** сначала измерения на железе; готовые движки (Strata upstream, llama.cpp, ik_llama,
   ExLlamaV3) и база A как строки одной матрицы; своё — только по измеренному разрыву (первый кандидат: политика кэша экспертов
   llama.cpp); база B и DFlash2-движок заморожены с проверяемым условием разморозки; оракул `ref/dflash2.py` — KEEP.
   ≥ 4 бит — правило `tools/gguf_quant_audit.py`, а не имя файла: GLM/Qwen `UD-IQ4_XS` исключены.
