## 0. Top findings (read this first)

1. **For GLM-5.3-Flash the NVMe tier is not needed for weights and must stay off the per-token path.** UD-Q4_K_XL
   experts are 186.1 GB (VERIFIED arithmetic from the measured 177,528 MiB in `PROBLEMS.md:62`); VRAM + RAM hold all of
   them (`../ROOFLINE.md` §2: 61% VRAM / 39% RAM / 0% NVMe, PROVISIONAL). Every 1% of routed bytes served from NVMe
   costs ~2.6 GB/s at 50 tok/s and, in the cost model (§8), drops the 8-channel bound from 34.4 to 27.9 tok/s
   (HYPOTHESIS). NVMe is the right place for: n-gram/PLE and Engram tables (deterministic addresses, a few KiB per
   token, prefetchable), persistent prefix/KV caches, recurrent-state checkpoints and session files.
2. **Deterministic lookup tables on SSD do not hurt 80+ tok/s when read correctly.** A community Strata run decodes
   Qwen3.8-Flash-Next UD-Q4_K_XL at a median 86 tok/s on 2x RTX 3080 20 GB with the 28.8 GB n-gram table on SSD
   (`--ple-io direct`), and the reporter measured `direct` speed-neutral against the table locked in RAM (REPORTED,
   Strata `bench/results/2026-10-08-community-2x-rtx3080-20gb-ud-q4-k-xl-512k-pool/README.md:5,106`@61b3fb5). The
   mechanism is VERIFIED in code: O_DIRECT 4 KiB reads by a 16-thread `pread` pool, a bounded set-associative row cache,
   and **prefetch of each MTP draft token's rows while the draft is produced** (`src/core/mtp.cpp:1297-1303`,
   `src/core/verify.cpp:1990-2019`@61b3fb5). This is the template for DeepSeek-V4.1-Flash Engram (48 rows/token).
3. **Prediction-driven PCIe prefetch of 15 MB experts cannot pay at batch 1, structurally.** A Gen4 x16 link lands
   `B_p * t_layer / S_e` = 25e9 x 0.44 ms / 15.4 MB ~= **0.7 GLM experts per layer** at 50 tok/s (HYPOTHESIS
   arithmetic), while ~3.1 of 8 experts miss per layer at 61% residency; the copy also steals DRAM bandwidth from the CPU
   that computes the other misses. Four independent field results agree: Strata's "Foresight swap" slots lost on every
   box measured (0.91-1.00x, VERIFIED text `docs/DETAILS.md:1650-1658`@61b3fb5), a Strata router-lookahead probe got
   recall 27-34% / precision ~8% on the fetch set and was closed (VERIFIED text,
   `bench/results/2026-10-04-community-rtx-5070ti-windows/README.md:117`), an ExLlamaV3 issue reports prefetch was a net
   loss despite 0.85-0.90 recall (REPORTED via search snippet), and a GH200 page-cache study measured +0.3% from router
   lookahead at 64.7% recall (REPORTED, arXiv 2608.12103 abstract). **Compute misses on the CPU in place; spend
   prediction on NVMe->RAM warming and on between-token cache adaptation, not on PCIe copies.**
4. **The thing that actually moves batch-1 hit rates is the cache policy, not the predictor**: profile-filled 50% ->
   adaptive 72% at 18% of experts resident (Strata Qwen3.8, VERIFIED text in `docs/paper/Strata-Paper.pdf` §3.4, §6 item
   4); KTransformers "dynamic expert update" 53 -> 70 tok/s at 10% GPU experts (REPORTED,
   `doc/en/kt-kernel/experts-sched-Tutorial.md`@5d048e5). But a 2026 methodology paper shows that trace replay semantics
   alone inflate recency policies by 27-29% and prompt-template contamination shifts results by 19-32 points
   (REPORTED, arXiv 2608.07911) - our `tools/g0/cachesim.py` must be checked against those two pitfalls.
5. **Public real routing traces exist, but none for our models.** `core12345/MoE_expert_selection_trace` on Hugging Face
   (DeepSeek-V3/R1 AWQ, Qwen3-235B, Llama4-Maverick, Kimi-K2; per request, per layer, per token expert ids; from
   "Patterns behind Chaos", arXiv 2510.05497) is the best public set (REPORTED; contents not opened - HF blocked here).
   GLM-5.3-Flash traces must be generated by us (`tools/g0/expert_trace.cpp`; the `traces-real` workflow (commit 8981351) in
   this worktree already targets a GitHub runner that can reach HF - the core12345 set can be fetched the same way).
6. **No engine examined uses io_uring.** Strata: `pread` thread pool (n-gram rows) and Linux AIO `io_submit` with
   O_DIRECT (experts); MoE-Infinity: `pread` pool + O_DIRECT; llama.cpp: O_DIRECT only as a load mode (VERIFIED, §4).
   io_uring is an optimisation for >100K IOPS per core; our per-token needs are <5K IOPS (Engram at 100 tok/s), so the
   choice does not matter for decode, only for prefill-time table gathers and prefix-cache restores (HYPOTHESIS).
7. **GPUDirect Storage on GeForce: UNKNOWN and irrelevant.** No source found that GDS (nvidia-fs) runs on GeForce;
   cuFile compat mode is POSIX read into host memory + copy (REPORTED, NVIDIA cuFile docs via snippet). The NVMe->GPU path
   is not on any plan here, because NVMe should not feed the GPU per token at all (finding 1).

weights at our target speeds.

- **Decode**: RAM->GPU copy of a missed GLM expert (615 us) is 5.7x slower than computing it on the CPU from RAM at
  8 channels (107 us) and 2.9x at 4 channels; the cost model gives 10.4 tok/s for "copy every miss" vs 34.4 for "CPU
  computes misses" at 61% residency (§8). Same conclusion as R3 §1.8, llama.cpp's `GGML_OP_OFFLOAD_MIN_BATCH=32`, and
  Strata's choice (DMA only for 20-55% of misses and only when the CPU is arithmetic-bound, paper §6 item 9).
- **Prefill / verify windows of many tokens**: copying pays when >= ~9-18 tokens share an expert (R3 §1.8); prefill
  streams experts per chunk (Strata: uses ~7 of 26 GB/s at 2,048-token chunks, paper §6 item 11).
- **Between-token cache refills** (adaptive tier) are the right use of the link: Strata copies up to 96 experts every 4
  rounds while the GPU drafts, evict-then-admit-after-landing 91.7 -> 94.4 tok/s (VERIFIED text, paper §6 item 10).

### 7.4 What this means for the scheduler (HYPOTHESIS, derived from §7.1 and §2)

- **Window available to a prediction** = prediction depth d x layer time. At 50 tok/s, d = 1 -> 0.44 ms, d = 3 ->
  1.3 ms. Experts one link can land in that window: `n_land = B_p * W / (S_e + B_p * L_p)` = 0.7 (d=1) / 2.1 (d=3)
  for GLM; recall at d = 2-3 is reported at 0.76-0.90 for the top-16 candidate set (i.e. precision <= 0.5). Without
  P2P, only the link of the GPU that owns layer l+d can deliver into its VRAM. So a perfect predictor moves at most
  0.7-2 of the ~3.1 per-layer misses to the GPU, while taking 15-31 MB of DRAM bandwidth from the CPU that computes the
  rest. The cost model (§8) shows a net loss (34.4 -> 32.6 tok/s at d=1; 29.6 at d=3, 8 ch) - consistent with the
  field results. **Do not build PCIe prefetch for GLM decode.**
- **Where prediction pays**: (a) NVMe -> RAM page warming when experts live on SSD (Strata +14%; cost model 5% on NVMe:
  20.4 -> 26.6 tok/s with p = 0.5 at d = 1); (b) the speculative-decoding window: draft tokens' routing is known before
  verification, which is exactly what MoE-SpAc and SP-MoE exploit (REPORTED); (c) lookup tables (100% accurate).
- **Where the hit rate comes from**: static profile + adaptive swaps between tokens (Strata), sized in bytes per layer
  (Strata +13% from byte-sized slots, paper §6 item 8). Candidate policies are already in `tools/g0/cachesim.py`; add
  Strata's adapt() rule (`tools/replay_cache_policy.py`, MIT) and SpecMD's "Least-Stale" as two more arms (HYPOTHESIS).

### 8.2 Formulas

```
U      = K                                if n_tok == 1   else  E * (1 - (1 - K/E)**n_tok)   # or measured
n_v    = h_v U;   n_r = h_r U;   n_s = h_s U
m      = n_tok K / U                                       # tokens per distinct expert in the step

# prediction (only experts not in VRAM are worth predicting)
n_pred = p (n_r + n_s);   n_waste = n_pred (1/pi - 1)

# NVMe: an expert is striped over all drives, staged to RAM, then computed by the CPU
per_s     = S_e / (B_s_drive n_drives)
pred_s    = p n_s  (if W > 0);   waste_s = pred_s (1/pi - 1);   unpred = n_s - pred_s
T_ssd     = unpred per_s + L_s (1 - (1 - unpred/U)**U)                 # demand reads (+ latency if any miss)
          + max(0, (pred_s + waste_s) per_s + L_s - W)                  # predicted reads overrunning the lead time

# optional PCIe prefetch into spare VRAM slots of this layer's GPU
n_land    = n_links_free B_p W / (S_e + B_p L_p)                       # experts a link can land within W
useful    = min(n_pred, n_land pi)
DMA       = min(n_pred + n_waste, n_land) S_e
n_gpu     = n_v + useful;   n_cpu = n_r + n_s - useful

# on-demand copy instead of CPU compute (miss_path == "pcie")
T_copy    = n_cpu (S_e/B_p + L_p);  DMA += n_cpu S_e;  n_gpu += n_cpu;  n_cpu = 0

T_gpu     = t_shared + n_gpu S_e / B_v + t_kern
T_cpu     = max( n_cpu S_e (1 + (m-1) gamma_mt) / (n_cpu_threads b_core),     # compute-bound
                 (n_cpu S_e + DMA) / (B_dram eta_dram) ) + t_sync            # DRAM-bound, DMA steals DRAM
T_off     = max(T_cpu, T_copy) + T_ssd                                       # pessimistic: SSD before CPU
T_layer   = t_pre + (max(T_gpu, T_off) if overlap else T_gpu + T_off)

T_step    = sum_layers T_layer + t_other        # t_other: lm_head, embeddings, sampling, PP hops (GLM 1.6e-3)
tokens    = (1 - accept**(k+1)) / (1 - accept)  with k = n_tok - 1
tok_s     = tokens / T_step

# lookup tables (Engram / PLE), per token, issued W_lookup before the consuming layer, cache hit c
T_lookup_exposed = max(0, L_s + rows (1-c)/(iops_drive n_drives) + rows (1-c) page/(B_s_drive n_drives) - W_lookup)
```

Pipeline (PP) over 4 GPUs: `T_step` sums all layers because one GPU works at a time; EP/TP variants are in
`tools/roofline.py` and can reuse `layer_time` with `B_v` scaled. The model ignores kernel-level compute limits on the
GPU, KV growth with context (put it in `t_pre`), and DRAM contention from more than one GPU link at a time.

## 9. Most promising technologies: algorithm and what it takes on our server

### 9.1 CPU-in-place miss execution with a doorbell (Strata; base A `--cpu-share`)
Call sequence (VERIFIED text, Strata paper §3.2; code `src/core/verify.cpp` around 1990-2100 @61b3fb5):
```
host: stage tokens; compute PLE rows for each window token; prefetch_rows()            # verify.cpp:1990-1996
host: cudaGraphLaunch(whole verify window)                                            # verify.cpp:2005
GPU, per MoE layer l: router -> write top-k ids to pinned "doorbell" ring; set seq flag
CPU pool (spinning): read ids; plan: VRAM hits -> GPU group; misses -> CPU jobs (+ optional DMA share)
CPU: quantise activations (q8_K), run kq_avx2 rows for missed experts, write partial sums to mapped memory, set flag
GPU: compute resident experts; wait flag; add CPU partials; continue layer l+1
```
For us: exists in Strata (Qwen3.8-FN) and base A (GLM, NVFP4 pack); for GLM GGUF it needs base B or a port of the
GLM graph into Strata (R2 direction B). Risk: low bits differ CPU vs GPU (R3 §1.2).

### 9.2 Deterministic-address table reader (Strata `PleTable`/`PleReader`) -> Engram
```
on token t sampled (and for each draft token as the draft head emits it):
    rows = hash(last n ids)                     # ngram_rows; Engram: 3 n-gram sizes x 8 heads x 2 layers = 48
    for r in rows: if row_cache.find(r): continue
        enqueue job(aligned 4 KiB page[s] of r)  # O_DIRECT, slot buffers, max_inflight 256
    io thread: submit to pread pool (16 threads) / io_submit; on completion: row_cache.insert, copy to destination
before the consuming layer: collect(ticket) -> rows in pinned buffer -> GPU
```
VERIFIED (`ngram.hpp:149-215`, `ple_reader.cpp:80-330`, `mtp.cpp:1297-1303`). For DS-V4.1 Engram: row = 264 B
(256 FP8 + 8 E8M0), two tables of ~384M rows each, 48 rows per token, layer-14 rows have a 13-layer lead time. Effort:
medium (MIT code, change hash/row format/table count). Risk: VM p99; DRAM row cache sizing (needs token streams).

### 9.3 Adaptive VRAM tier with evict-then-admit-after-landing (Strata `adapt()`)
VERIFIED as an offline replica in `tools/replay_cache_policy.py:1-12,53+`@61b3fb5:
```
usage[l,e] += 1 per routed entry; every `every`=4 windows:
  per layer: best non-resident (usage >= mincand=2.0) vs worst resident (needs margin 1.5x)
  take the best `swaps`=96 over all layers; evict at once; mark the new slot usable only when its copy has landed
  usage *= decay (0.7)
```
For us: port into `tools/g0/cachesim.py` as a policy (pure Python, ~60 lines) and evaluate on GLM traces before any
engine work. This is the cheapest experiment with the largest reported effect (50% -> 72%).

### 9.4 Prefix/KV/state persistence on NVMe
Strata conversation file (`src/core/conversation_file.cpp:79+`): aligned 16 MiB O_DIRECT blocks, hash-checked; park in
RAM first (bounded `--conversation-cache-mib`), spill to disk on `SAVE`. For GLM: 34 KDA states (145.6 MiB fp32) + 11
DSA latent/indexer caches; restore cost ~0.2-0.5 s from 4 drives vs ~50 s re-prefill at 262K (HYPOTHESIS, §3).
