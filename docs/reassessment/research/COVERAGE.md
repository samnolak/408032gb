Date: 2026-10-10. Scope: every project and direction that the customer's specification lists in §3.2 ("starting points of
the search": four groups plus the additional directions), checked against what the research reports R1–R10 in this folder
actually contain, and the gaps filled by R12 (`R12-gapfill.md`, rows in `matrix/R12-gapfill.json`). The companion
deliverable B is `MATRIX.md` (generated by `tools/research/merge_matrix.py` from `matrix/R*.json`).
R11 (`R11-verification.md`, written concurrently by another agent) is not part of this audit.

**Labels.** VERIFIED = I read the cited section of the report (or the code at the SHA, for R12 items); REPORTED = stated by a
report that itself only had a README/paper/snippet; HYPOTHESIS = my judgement; UNKNOWN; NOT FOUND (searches listed).
AGENTS.md mapping: VERIFIED = CONFIRMED, REPORTED/HYPOTHESIS = PROVISIONAL.

## Method

1. Grep of every report for every listed name (literal output in the appendix), then reading the hits in context.
   Depth was judged from what each report cites, not from section titles.
2. Depth scale (a row takes the deepest level any report reaches):
   - **code-read**: a report cites `path:line` or a function at a recorded SHA for the mechanism in question (or ran it).
   - **docs/README**: a report read README / docs / benchmark files at a recorded SHA, but no source code of the mechanism.
   - **mention**: name, URL/SHA and at most one line of description.
   - **not covered**: no report mentions it.
   - **NOT FOUND**: a report (or R12) searched and found no repository/code; the searches are given there.
3. For every "not covered" or "NOT FOUND" item R12 searched again and, where code existed, read it (`R12-gapfill.md`).
