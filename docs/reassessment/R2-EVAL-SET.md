# R2.2 — оценочный набор заказчика: что собрать и в каком формате

Зачем: публичные индексы (Artificial Analysis и др.) различают кандидатов на 2–4 пункта и противоречат друг другу между
версиями (research/R1 §2.2). Выбор модели и кванта (ADR-013) делается на **задачах заказчика**, в 4 битах, на 32K–262K.
Набор собирает заказчик (или даёт материалы), прогоняет стенд `tools/bench/` на всех кандидатах одним харнессом.

## Состав (минимум 60 задач; лучше 100)
| часть | сколько | что это | как проверять |
|---|---|---|---|
| A. code-агент | 20–40 | реальные задачи из репозиториев заказчика: «исправь баг / добавь функцию / напиши тест», со снапшотом репозитория и командой проверки | команда теста возвращает 0 (выполняет харнесс заказчика); доля решённых |
| B. длинные документы | 15–30 | документы/кодовые базы 32K–262K токенов + вопросы с однозначными ответами (факт из середины, сравнение двух мест, вычисление по таблице) | точное совпадение / набор допустимых ответов |
| C. tool calling | 10–20 | сценарии с 2–5 инструментами (JSON-схемы), многоходовые, с ответами инструментов | верное имя функции + валидный JSON аргументов + итоговый ответ использует результат |
| D. рассуждение/чат | 10–20 | типичные вопросы пользователей заказчика | рубрика 0–2 от человека вслепую (без имени модели) |

## Формат (JSONL, одна задача на строку)
```json
{"id": "B-017", "part": "B", "context_files": ["docs/spec-v3.pdf.txt"], "context_tokens_hint": 180000,
 "messages": [{"role": "user", "content": "<вопрос>"}],
 "tools": null,
 "check": {"type": "exact_any", "answers": ["42 мс", "42ms"]},
 "notes": "ответ в разделе 7.3; ловушка — устаревшее значение в разделе 2"}
```
Типы проверки: `exact_any`, `regex`, `json_schema` (+ обязательные поля), `tool_call` (имя + JSON-схема аргументов),
`command` (для части A: команда в снапшоте репозитория, код возврата 0), `human_rubric` (часть D).

## Правила
- Задачи не публикуются и не попадают в обучающие данные (локальный сервер).
- Одинаковые промпты, температура 0 (и отдельный прогон с рекомендованными вендором параметрами сэмплинга), одинаковый шаблон чата
  модели, одинаковый лимит токенов ответа; reasoning-бюджет фиксируется.
- Каждая модель × квант × движок прогоняется полностью; результат — доля по частям + доверительный интервал (бутстрап).
- Решение ADR-013 учитывает разницу, только если она больше разброса повторов.

## Что нужно от заказчика
Материалы для частей A–C (репозитории/документы, которые можно использовать) или разрешение собрать их из его реальных
сессий code-агента; список типичных вопросов для части D.
