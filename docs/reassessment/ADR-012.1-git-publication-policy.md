# ADR-012.1. Политика публикации рабочих веток агентов (решение заказчика, 2026-10-10)

**Статус:** ПРИНЯТО. Решение владельца репозитория в сессии 2026-10-10 (дословно: «разрешаю публикацию рабочих веток в GitHub»;
«Разрешаю агентам обычный `git push` исключительно в рабочие ветки `claude/*`»; «Запрет на force-push, удаление удалённых веток,
изменение `main`, публикацию секретов и обход защиты сохраняется»). Дополняет ADR-012; заменяет правило «no git push from agents»
старого хука и делает предложение `proposals/0001` применённым (с усилениями ниже).

## Контекст
- Облачный контейнер агента удаляется после сессии; до этого решения работа сохранялась только git-бандлом, переданным файлом в
  чат. Подписка может закончиться раньше, чем будет собран сервер, — результаты должны лежать в `samnolak/408032gb`.
- Изолированная VM инференса интернета не имеет и по-прежнему синхронизируется бандлами (skill `bundle-sync`).
- Старый хук блокировал любой `git push`, но пропускал `git -C <dir> push …` (дыра, CONFIRMED в `proposals/README.md`).

## Решение
1. Агенты сами создают ветки `claude/*`, коммитят промежуточные результаты и публикуют их обычным fast-forward push:
   `git push [-u|--set-upstream] origin [HEAD:][refs/heads/]claude/<имя>` — только в `origin` = github.com/samnolak/408032gb и
   только из каталога проекта. Разрешение на каждый push не требуется.
2. Агенты открывают **Draft** pull request из `claude/*` в `main` (или в другую `claude/*`). Merge и auto-merge — только владелец.
3. Запрещено: push в `main` и любые ветки вне `claude/*`; force-push в любой форме (`--force`, `-f`, `--force-with-lease`,
   `+refspec`); удаление удалённых веток и тегов (`--delete`, `-d`, `:ветка`); `--mirror`, `--all`, `--tags` и другие опции push;
   другие remote, форки и URL; изменение remote, refspec (`remote.origin.push`), `insteadOf`, алиасов git ради обхода; push через
   обёртки, вложенные shell и `VAR=… git push`; переписывание истории (`reset --hard`, `rebase -i`, `filter-branch`,
   `filter-repo`); запись в GitHub в обход git (`gh pr merge`, `gh api` с методом не GET, `curl -X DELETE/PUT/PATCH/POST`,
   GitHub-инструменты merge/delete/запись вне `claude/*`); публикация секретов.
4. Перед каждым разрешённым push хук сканирует добавленные строки и имена файлов коммитов, которых ещё нет на origin
   (`scripts/hooks/secret_scan.py`: приватные ключи, токены GitHub/AWS/Anthropic/OpenAI/HF/Google/Slack, логин:пароль в URL,
   `.env`, `*.pem`, `id_rsa` …). Находка блокирует push; значение секрета не печатается.

## Как обеспечено
| что | где |
|---|---|
| Bash: git/gh/curl | `scripts/hooks/guard-bash.sh` → `scripts/hooks/guard_bash.py` |
| GitHub MCP-инструменты | `scripts/hooks/guard-github.sh` → `scripts/hooks/guard_github.py` |
| секреты в исходящих коммитах | `scripts/hooks/secret_scan.py` (вызывается из guard_bash; можно запускать вручную, `--all` — весь трекаемый код) |
| подключение | `.claude/settings.json` (PreToolUse: `Bash`, `Edit|Write`, `mcp__github__.*`) |
| тесты | `tests/test_hooks.py`: разрешённые и запрещённые команды, условия репозитория во временных репозиториях (origin, refspec, `pushInsteadOf`, алиасы, тег вместо ветки, другой каталог, секреты в исходящих и уже опубликованных коммитах), сами hook-скрипты с JSON как у Claude Code, «сломанный хук блокирует» |
| правила для агентов | `AGENTS.md` «Git and sync», `CLAUDE.md`, `.claude/skills/bundle-sync/SKILL.md` |

## Ограничения (честно)
- Хук — защита от ошибок и случайного обхода агентом, а не от человека с доступом к машине: правила можно изменить, отредактировав
  сам хук. Поэтому изменение правил — только отдельным решением заказчика с обновлёнными тестами (AGENTS.md).
- Сканер секретов узкий (известные форматы); незнакомый формат токена он пропустит. Секреты в репозиторий не кладутся вообще.
- Защита ветки `main` на стороне GitHub (branch protection) — настройка владельца в GitHub; агент её не меняет. Рекомендуется
  включить «Require a pull request before merging» и запрет force-push для `main` (решение владельца).

## Откат
Вернуть старое поведение «никаких push» — заменить тело `check_git_segment` для `push` на безусловную блокировку и обновить тесты и
AGENTS.md; работа тогда снова передаётся бандлами.
