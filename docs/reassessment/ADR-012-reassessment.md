# ADR-012. Переоценка 2026-10-09: платформа «сначала измерения», модель и движок выбираются по железу заказчика

**Статус:** ПРИНЯТО ПРЕДВАРИТЕЛЬНО, **редакция 2** (ведущий агент переоценки, 2026-10-09; исправления по независимому ревью
`REVIEW-adversarial.md`, п. 1, 3, 10, 12, 16, 17, 19; первая редакция — в истории git, коммит `393cbc1`). Окончательные пункты D2
(модель) и D3 (движок) подтверждаются или меняются только по результатам гейтов R1–R2 (`ROADMAP.md`). Заменяет как рамку проекта:
ADR-001, 002, 005 (вариант IQ2/IQ3), 006 (частично), 010 (п. 2–3); переводит в REVALIDATE/заморозку ADR-003, 007, 009, 011.
Классификация — `LEGACY_AUDIT.md`. Старые ADR не удаляются; в `docs/DECISIONS.md` стоит ссылка на этот документ.

## Контекст

1. **Новые требования заказчика** (мастер-промпт 2026-10-09) выше исторических решений: лучшее практическое качество open-weight
   моделей для code-агентов/рассуждений/tool use/длинных документов; **≥ 262 144 реально используемых токенов**; single-stream декод
   **50 tok/s минимум, 80–100+ желательно** при заполненном контексте; основные веса **≥ качественного 4-бит**; точная маршрутизация;
   VRAM→RAM→SSD там, где окупается; сервер с API и кэшем префиксов.
2. **Аудит репозитория** (`REPO_AUDIT.md`): своего GPU-кода нет; ни одного запуска на 4×4080; 262K и Q4-минимум в старом плане не
   учтены; P2P и состав железа — заявления, не замеры. Реальные замеры GLM-5.3-Flash есть только с чужого стенда 1×3090 + RAM
   (PROVISIONAL/REPORTED): ik_llama.cpp UD-Q4_K_XL — 15.0 tok/s (8K); база A (strata-glm-3090, NVFP4-пак 171 GB) — 6.85 → **13.89 tok/s**
   с `--cpu-share`, 14.12 со `--spec 3`; повтор эксперта от предыдущего токена — 24.6% (research/R2 §3.4).
3. **Физика** (`ROOFLINE.md`, редакция 3, PROVISIONAL): при batch=1 конвейер по слоям ограничен полосой одной карты. GLM-5.3-Flash
   (UD-Q4_K_XL, 4.89/8.04 bpw): конвейер без спекуляции ≤ ~42 tok/s при любом попадании; со спекуляцией (принятие 0.7) граница
   50.6–52.9 только с перекрытием CPU/GPU и при попадании ≥ ~0.8 (перекос маршрутизации), без перекрытия (llama.cpp) ≤ ~47; при TP
   латент MLA реплицируется, TP@auto ≈ 41 — **без TP плотной части пол 50 tok/s при 262K для GLM — граница «на пределе» при сильном
   перекосе маршрутизации, цель 80–100 недостижима**. Qwen3.8-Flash-Next (всё в VRAM): граница конвейера 84–87, со спекуляцией
   95–101. Полное внимание на 262K читает гигабайты KV на токен.
4. **Исследования** (`research/R1…R4`): на индексе Artificial Analysis v4.3 модели, физически помещающиеся в сервер в 4 битах, близки
   по качеству (REPORTED, версии индекса конфликтуют: GLM-5.3-Flash 42, Qwen3.8-Flash-Next 40, DeepSeek-V4.1-Flash 39, MiMo 38;
   DeepSeek-V4-Flash-0731 — UNKNOWN, конфликт 25/34). **Qwen3.8-Flash-Next** (125B + 51B n-gram, 6B активных, 262K нативно) помещается
   в 120 GB VRAM в UD-Q4_K_XL (111.3 GB вместе с n-gram-таблицей, которая живёт в RAM). Чужие замеры этого файла (REPORTED):
   - Strata, **1×RTX PRO 4500 32 GB (Blackwell, GDDR7)**, TR PRO 3975WX AVX2, 512 GB RAM, `--resident-budget-gib 100` (70% экспертов в
     RAM), **MTP `--spec 4` включён** (обязателен в serve-режиме этой версии), **KV int8**, окна процессов 8 192 / 81 920 / 139 264
     (не 262K), синтетические code-промпты: 61.5 / 72.1 / 70.2 tok/s при 2.7K / 64K / 128K;
   - Strata, 2×RTX 3090 split, 165 GiB RAM: 64–78 tok/s, 55 при промпте 128K (`docs/UNSLOTH_Q4.md:34-35`@fb58e0d);
   - llama.cpp: 2×5090 — 53.2 / 46.1 tok/s при 10K / 87K (36.1 на 87K в другом прогоне); форк на 6×4090 — 21.0 → 48.7 tok/s при 250K
     после доработок (research/R2 §4, строки 14, 17).
   Ни у кого нет замера UD-Q4_K_XL при заполненных 262K на 4 картах; **50+ при 262K не гарантированы и для Qwen**.
   На штатном драйвере GeForce P2P выключен (R4); vLLM на >2 PCIe-GPU без NVLink отключает свой all-reduce (R3, код).
5. **Движки** (`research/R2-engines.md`, ключевое проверено ведущим): в llama.cpp с 2026-10-07 — GPU-кэш экспертов из RAM
   (`--moe-cache-mib`, `d6cf9acb2`; LRU на устройство, синхронная подгрузка промахов по PCIe — `src/llama-moe-cache.cpp`@10a60cf30),
   с 2026-10-08 — на нескольких GPU (`c811cb8f0`); TP для `glm5-next` нет ни в llama.cpp, ни в ik_llama (`llm_arch_supports_sm_tensor`
   исключает GLM5_NEXT, `src/llama-arch.cpp:1205-1240`@79e2e74); ExLlamaV3 v1.6.0 заявляет TP/EP без NCCL и P2P; DSA-индексер в vLLM
   требует DeepGEMM (Hopper/Blackwell) → GLM в vLLM на sm_89, вероятно, не запустится (HYPOTHESIS); Strata upstream ушёл от пина на
   1552 коммита и остаётся однопородным. Чужие замеры GLM на 3090-классе с выгрузкой: 6–20 tok/s, но **в IQ4_XS-паках неизвестного
   состава (вероятно, частично 3-бит) и Q2_K** — к требованию ≥4 бит напрямую не относятся (ревью, п. 1).

## Решение

**D1. Цели и критерии приёмки** — требования заказчика становятся сквозными критериями всех гейтов. Флаг `--ctx-size 262144` не PASS:
нужны пробы качества на полной длине (`tools/bench/probes.py`, режим `--length-mode total`) и декод, измеренный при заполненном
контексте (`tools/bench/run_matrix.py`). У моделей с нативным окном ровно 262 144 (Qwen3.8) промпт ≈ 262K + вывод выходит за окно —
это мерить явно (с YaRN и без) и записывать (ревью, п. 16).

**D2. Модель — по Pareto «качество ↔ скорость ↔ контекст ↔ надёжность». Шорт-лист = порядок первых замеров (не ранжирование качества):**
1. **Qwen3.8-Flash-Next, UD-Q4_K_XL** — первым меряем, потому что это единственный кандидат шорт-листа, у которого граница 50+ при
   262K достижима без TP, и его дешевле всего поднять (зрелый Strata). Лицензия Qwen Community License 1.0 (REPORTED: отдельная лицензия
   для MaaS/«AI work assistant» третьим лицам) — **решает заказчик**. Риск движка: setup Strata рекомендует для split ≥ ~135 GB RAM,
   у сервера 128 GB; это рекомендация, а не запрет («128 GB ran it fine», #737, REPORTED) — `BRINGUP-qwen38fn.md`.
2. **Запасной лицензионно чистый кандидат класса «всё в VRAM»** — один из Qwen3.5-122B-A10B (Apache-2.0, 262K нативно), Nemotron-3-Super
   (NVIDIA Open Model License), Ling-3.0-flash (лицензия UNKNOWN): их качество на задачах заказчика — **UNKNOWN**, а не «слабое»
   (research/R1 §2); первым в этой группе меряется Qwen3.5-122B-A10B (Apache-2.0, есть официальный GPTQ-Int4 и GGUF), после
   `gguf_quant_audit.py` (ревью, п. 12).
3. **GLM-5.3-Flash, UD-Q4_K_XL** (MIT) — сильнейший по качеству среди помещающихся (REPORTED); требует VRAM+RAM; 50+ при 262K —
   только с TP плотной части (его нет в готовых движках) и/или спекуляцией при сильном перекосе маршрутизации.
4. **DeepSeek-V4-Flash-0731, UD-Q4_K_XL** (MIT) — родные FP4-эксперты (REPORTED: бит-в-бит), ~82% экспертов в VRAM; **качество UNKNOWN**.
5. **MiMo-V2.6-Flash-MOPD, MXFP4** (MIT) — родной 4-бит; на 262K дорогое полное внимание; готового GGUF для MOPD нет (есть для `-RL`) —
   нужна конвертация из safetensors (173 GB) и аудит битности.
Вне шорт-листа скорости: DeepSeek-V4.1-Flash (NVMe в активном пути, ~10 tok/s при 3 NVMe; ~12 при 4 — поправка 2026-10-12; PROVISIONAL, модель `tools/roofline.py`, `ROOFLINE.md` п. 5, не замер) — эталон качества. Выбор фиксируется ADR-013 по
итогам R2 (качество на задачах заказчика в 4 битах + скорость на 262K).

**D3. Движок — направление A (готовые движки без форка) как база, своё — только по измеренному разрыву:**
- Бейзлайны R1: Strata upstream (Qwen3.8), llama.cpp mainline и ik_llama.cpp (все GGUF-кандидаты; `-sm layer/row/tensor/graph` где
  есть; `-ot`/`--n-cpu-moe`; `--moe-cache-mib`), ExLlamaV3 (TP/EP без P2P — проверить заявление; ExLlamaV3 — MIT, сервер TabbyAPI —
  AGPL-3.0: без модификации и раздачи допустимо), **база A (strata-glm-3090 / наши патчи) для GLM — отдельной строкой матрицы**
  (единственный путь GLM с перекрытием CPU/GPU, ревью п. 10), FreeToken (один GPU; донор политики гибрида), vLLM/SGLang — только для
  конфигураций целиком в VRAM и поддерживаемых на sm_89, с замером цены all-reduce без P2P.
- Первый кандидат для D: политика llama.cpp `--moe-cache-mib` против профиля/TinyLFU и счёта промахов на CPU — сначала симулятор
  (`tools/g0/cachesim.py`, политика `lru_device` — приближение llama.cpp), затем патч `patches/llama.cpp/` с бенчмарком до/после
  (`D1-moe-cache-policy.md`).
- Своя разработка ограничена тем, чего нет в готовых движках и что даёт измеримый выигрыш: инструменты замеров (закоммичены с тестами:
  roofline, трассы маршрутизации, симулятор кэша, стенд бенчмарков, сравнение логитов, K3, аудит битности, диагностика), эксплуатационный
  слой (API-шлюз, кэш префиксов/снимки на NVMe, наблюдаемость, health/restart, доступ), затем при необходимости — **D: планировщик
  размещения экспертов и TP плотной части поверх выбранного рантайма**.
- **E (новый рантайм) не начинается**, пока A–D не исчерпаны и roofline (откалиброванный на сервере, в том же режиме) не показывает
  запас ≥ 1.5× над лучшим измеренным движком.

**D4. Старые базы и треки** (HISTORICAL, без удаления): база B (lighttransport) и «день GPU» заморожены. База A для GLM входит в матрицу
R1 (см. D3). **Условие разморозки базы A как основы GLM-пути (проверяемое):** на сервере, на GLM-5.3-Flash 4-бит класса, при 32K и 128K
её single-stream декод ≥ 1.1× лучшего движка направления A при сопоставимом качестве (`tools/quality/logprob_compare.py`, top-1 ≥ 0.9).
DFlash2: движок не делается; оракул `ref/dflash2.py` (CONFIRMED против vLLM) — **KEEP** как проверка реализаций DFlash/DFlash2 в
llama.cpp/ik_llama для эксперимента S3 (ревью, п. 19).

**D5. Квантование — правило, а не имя файла:** каждый маршрутизируемый тензор экспертов и каждая неэкспертная матрица ≥ 4 bpw по
`tools/gguf_quant_audit.py` (FAIL иначе); имена `*IQ4_XS*`, `UD-*`, «Q4» сами по себе ничего не доказывают. **Исключены:** UD-IQ4_XS
Qwen3.8-Flash-Next (эксперты gate/up — IQ3_S, Strata `docs/UNSLOTH_Q4.md:234-236`@fb58e0d) и UD-IQ4_XS GLM-5.3-Flash (156.82 GB
арифметически даёт < 4 bpw в среднем по экспертам — ревью, п. 1); утверждение R2 «UD-IQ4_XS может пойти без новых ядер в базе B»
для обеих моделей — DISPROVED как путь к ≥ 4 бит. Допустимы после аудита: UD-Q4_K_XL, Q4_K_M и выше, родные MXFP4/FP4, AWQ/GPTQ-INT4
(для не-GGUF аудит — UNKNOWN, нужен отдельный инструмент). Q2/Q3 — только отдельный экспериментальный режим с измеренным штрафом.
NVFP4 на sm_89 — W4A16-фолбэк, низкий приоритет. KV: f16 по умолчанию; FP8/Q8 — после эксперимента K2 (накопление в fp32).

**D6. Многокарточность:** базовый режим — конвейер по слоям (не требует P2P). TP/EP — после замеров H6 (P2P) и P2 (all-reduce).
Патч драйвера для P2P на GeForce (tinygrad/aikitoria) — **опциональный эксперимент с явного согласия заказчика** (R4 §4.2).

**D7. Ярусы памяти:** VRAM — активные веса и KV; промахи мимо VRAM при batch=1 считать на CPU из RAM, а не копировать по PCIe
(гипотеза M4: следует из полос, проверяется замером; в llama.cpp сейчас наоборот); NVMe — холодные данные: файлы моделей, снимки
KV/состояния, n-gram/Engram-таблицы, профили маршрутизации; **в активном пути экспертов NVMe не используется** для целей 50+.
Все 3 NVMe (3 × 1 ТБ, поправка заказчика 2026-10-12; было «4») — для независимых файлов и параллельного чтения: по умолчанию 2 диска
под веса, 1 — под состояния/логи (PROVISIONAL, `DEPLOY.md` §1); RAID0 против шардинга — по замеру H7/P3.

**D8. Длинный контекст и повторные агентные запросы:** кэш префиксов и сохранение/восстановление состояния (KV + рекуррентные
состояния) — обязательная часть платформы: граница TTFT префилла 262K — десятки секунд (GLM ~50 с, MiMo ~98 с, PROVISIONAL; по
FP16-тензорным ядрам — для движков с INT8-префиллом это не нижняя граница, `ROOFLINE.md` §4 п. 6), а у агентов контекст растёт
каждым ходом. Проверка — K3 (`tools/kv/slot_persist.py`) и пробы B3.

## Цена ошибки и откат
- Если Qwen3.8-Flash-Next не проходит по лицензии или качеству — следующий в замерах запасной кандидат класса «всё в VRAM» (D2 п. 2),
  затем ярусные GLM/DeepSeek-V4-Flash; инструменты и стенд модель-агностичны.
- Если готовые движки на сервере окажутся далеко ниже откалиброванных на том же сервере границ — это сигнал к D/E, а не к понижению
  битности. Порог «далеко» задаётся после R0/R1 (калибровка 3090-хоста к серверу не переносится, ревью п. 4).
- Откат решения: вернуть статус ADR-007/009/010 из `docs/DECISIONS.md` (там ничего не удалено), разморозить треки.

## Что решает заказчик (не инженерные вопросы)
1. Допустима ли Qwen Community License 1.0 для его сценария использования (юридический вопрос).
2. Согласие на установку модифицированного драйвера NVIDIA для P2P (опционально, после замеров).
3. Окна простоя для BIOS-шагов и (если это хост Proxmox) перезагрузок.
4. Материалы для оценочного набора R2.2 (`R2-EVAL-SET.md`).
