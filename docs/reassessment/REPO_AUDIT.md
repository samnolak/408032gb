# Repo Reality Audit — 408032gb на 2026-10-09

Аудитор: ведущий агент переоценки (облачная сессия, без GPU). База: `main` = `eb59224` (литеральный снимок —
`docs/reassessment/SNAPSHOT-2026-10-09.md`). Метки: **CONFIRMED** (проверено здесь: команда/файл:строка@коммит/URL),
**PROVISIONAL** (оценка, способ указан), **UNKNOWN**. Классификация каждого ADR и гейта — `LEGACY_AUDIT.md`.

Мастер-промпт заказчика (2026-10-09) прямо делает этот репозиторий **объектом исследования**, а не ТЗ. Ниже — что в нём
реально есть, что доказано, что нет, и что конфликтует с актуальными требованиями.

---

## 0. Итог в десяти пунктах

1. **Своего движка нет.** В репозитории 0 строк своего CUDA-кода (`kernels/` не существует; CI-job `cuda-compile` печатает
   «no kernels yet» и зеленеет — CONFIRMED, `.github/workflows/ci.yml:56-60`). Весь GPU-код — два чужих форка Strata, к одному
   из которых приложено 6 патчей (+397/−168 строк, CONFIRMED подсчётом строк `+`/`-` в `patches/strata-glm/*.patch`:
   Linux-порт, ярус RAM, разбиение по слоям).
2. **Ни одного запуска на целевом сервере 4×4080.** G0 (железо) не выполнен; все цифры по серверу — модельные (`tools/fitplan.py`)
   или заявления заказчика. Единственные реальные запуски — на чужом стенде 3×RTX 3090 (sm_86). С реальными весами там два замера
   (исправлено после ревью, `REVIEW-adversarial.md` п. 10): **ik_llama.cpp** UD-Q4_K_XL — pp 166.8 / tg 15.0 tok/s, контекст 8192, одна
   карта + эксперты в RAM (PROVISIONAL: замер оператора того хоста, `PROBLEMS.md`); **база A** (strata-glm-3090 `794cd69`, NVFP4-пак
   171.2 GB) — декод 6.85 → 13.89 tok/s с `--cpu-share`, 14.12 со `--spec 3`, повтор эксперта от предыдущего токена 24.6% (REPORTED,
   `PROBLEMS.md`@794cd69 форка; `research/R2-engines.md` §3.4). Кванты и промпты разные — «база A не быстрее» не доказано.
3. **Цифры strata-glm на 3090 (19.65 tok/s декод, 438 tok/s префилл) получены на синтетическом паке**, где 40 из 42 MoE-слоёв —
   нули и 99.2% экспертов отдаются из VRAM (`docs/evidence/2026-10-03-3090-review.md`, caveats 1–2). Это потолок плотной части, а не
   прогноз; в `PROBLEMS.md` они сравниваются с реальными 15 tok/s ik_llama — сравнение некорректно.
4. **Ценная, проверенная часть — эталоны и parity-инфраструктура на CPU:** numpy-оракулы KDA, mHC/Sinkhorn, k-pool индексер DSA,
   MLA без RoPE, роутер sigmoid+noaux_tc, SwiGLU-clamp (GLM), внимание MiMo (SWA+sinks+GQA+частичный RoPE), примитивы DFlash2;
   сверены с реальными графами llama.cpp @`ec7630a` на крошечных моделях и с vLLM (CONFIRMED в CI по evidence-логам). Это переносимо
   на любой выбранный движок как тест корректности.
5. **Требование 262 144 токенов контекста нигде не учтено.** Ни один гейт, тест или документ не ставит цель 262K; примеры используют
   8K–131K (`README.md:40`, `PROBLEMS.md`). Нет ни одного теста качества на длинном контексте.
6. **Требование «не ниже качественного 4-бит» противоречит действующим ADR:** ADR-010 делает первой очередью UD-Q2_K_XL, ADR-005/G5
   сравнивают IQ2/IQ3 «почти всё в VRAM», ADR-001 предполагает переквант DeepSeek до ≤3 бит.
7. **Ложная определённость по железу:** P2P записан как «CONFIRMED (stated by the customer)» (`hardware/4x4080s-32g.json`), «P2P works»
   (`AGENTS.md`), «P2P работает на этом сервере, CONFIRMED заказчиком» (`docs/design/G4-glm-multigpu.md`). Заявление ≠ измерение; на
   GeForce P2P обычно выключен драйвером (проверяется в R4). NVMe записано 3 шт., заказчик теперь говорит 4.
8. **Модельный инструмент `tools/fitplan.py` не учитывает чтение KV/состояния на токен при длинном контексте**, PCIe-передачи,
   реальную эффективность ядер и CPU-вычисления; его «потолки» 61–150 tok/s — верхние оценки только по весам. Для 262K это
   существенная ошибка для моделей с полным вниманием (см. п. 4.3).
9. **Нет сервера/API/кэша префиксов в собственной кодовой базе.** OpenAI-совместимый сервер, prefix cache, повторные агентные
   запросы, tool calling — только как заявления авторов форков (база B: «нет prefix reuse, батчинга, разбора tool-call»).
10. **Процесс и дисциплина доказательств — сильная сторона:** метки, литеральные логи, пины, патчи вместо правок апстрима,
    вендоринг с проверкой git blob id, мутационные проверки тестов. Это сохраняется.

## 4. Ложная определённость (что выглядело фактом, а им не является)

### 4.1 Железо
- P2P «CONFIRMED (stated by the customer)» — заявление, не замер (C2). Пропускная способность HBM 736 GB/s у «32 GB 4080 Super» —
  PROVISIONAL (сам JSON это признаёт): модифицированные платы могут иметь другую шину/частоту памяти.
- Каналы DDR4 — UNKNOWN (сам JSON признаёт). Все потолки fitplan печатаются для 4 и 8 каналов — разница в 2 раза на RAM-ярусе.
- «Proxmox host; VM без интернета» — историческое сведение; если инференс в VM, P2P и NUMA зависят от passthrough.

### 4.2 Модели и веса
- «GLM active 17–18B» помечено UNKNOWN в самом ТЗ; по геометрии `models/glm-5.3-flash.json` маршрутизируемых активных
  8 × 42 × 25.17M = 8.46B, плотных ≈ 7.1B без эмбеддинга (PROVISIONAL, арифметика fitplan) → ≈ 15.5B, не 18B. **Объяснено
  после ревью:** спецификация `models/specs/glm-5.3-flash.json` по формам тензоров llama.cpp даёт ≈ 16.7B активных без эмбеддинга и
  17.4B с ним (PROVISIONAL, тест `test_glm_active_is_17_to_18b_with_embedding_row_counted_as_weights`; E11/E55 в `EVIDENCE_MATRIX.md`);
  у fitplan плотная часть занижена.
- GGUF-диалекты `glm5-next` (llama.cpp) и `glm5next` (Unsloth/ik_llama/база B) — CONFIRMED несовместимы по метаданным;
  «тензоры совместимы» — слова автора форка (PROVISIONAL).
- Размеры чекпойнтов (NVFP4 204 GB, UD-Q4_K_XL 186 GiB, UD-Q2_K_XL 101.25 GiB) — из README авторов/замера чужого хоста;
  перепроверяются в R1.

### 4.3 Производительность
- Потолки fitplan считают только веса. При 262K контексте модели с полным вниманием читают весь KV глобальных слоёв **на каждый
  токен**: для MiMo (9 глобальных слоёв × 4 KV-головы × (192+128) × 2 байта ≈ 23 КБ/токен, PROVISIONAL из `models/mimo-v2.6-flash.json`)
  это ≈ 6 ГБ на токен при 262K — сравнимо с весами (≈ 9 ГБ/токен по fitplan) и снижает потолок примерно с 77 до ~47 tok/s (1/(1/77 + 6.04 ГБ / 736 ГБ/с))
  (PROVISIONAL, та же модель «только память»). Для GLM (DSA читает пулы индексера + 2048 выбранных латентов; KDA — фиксированное
  состояние 34 × 64 × 128 × 128 × 4 Б ≈ 143 МБ fp32, читается и пишется каждый токен) рост от контекста меньше, но не ноль. Нужен roofline с этими членами.
- «Конвейер по слоям, P2P не нужен» (ADR-003) верно для корректности; для скорости single-stream конвейер загружает одну карту из
  четырёх в каждый момент — потолок ≈ полоса одной карты.
- Цифры strata-glm 19.65 tok/s и «6× быстрее llama.cpp» (README автора) — синтетика и чужое железо соответственно.

### 4.4 Процесс
- Зелёный `cuda-compile` без файлов; «G2 сборка CONFIRMED» — это сборка чужого движка, не корректность.
- `scripts/gpu_day.sh` предполагает интернет на VM (`git clone`), которого по AGENTS.md нет.
- `docs/strata-tiered-run.md` называет `tools/glm_pack.py` Windows-only, хотя патч 0006 портирует его на Linux (замечено и в
  evidence 2026-10-03-3090-review, п. 6) — документ не обновлён.
