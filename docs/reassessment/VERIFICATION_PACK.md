# VERIFICATION PACK — состав и правила приёмки (2026-10-09)

**Статус: состав и сборщик готовы, самого pack НЕТ (НЕ ВЫПОЛНЕНО).** На целевом сервере не снято ни одного артефакта. Сборщик
`tools/verify/pack.py` (обёртка `scripts/verify_pack.sh`) проверен только на синтетических артефактах (`tests/test_verify_pack.py`);
при отсутствии артефактов он выдаёт NOT RUN, а не PASS. Документ закрывает часть BLOCKER 2 ревью (`REVIEW-adversarial.md`) и задачу
ROADMAP R6.1; сборка на сервере — R6.2.

## Зачем
Один каталог, по которому заказчик (или evidence-auditor) без доступа к сессии агента проверяет каждое требование: что измерено, чем,
на каком коммите, с каким результатом. Число без артефакта в pack не считается (AGENTS.md: «a number without a command is invalid»).

## Критерии (сводка; точные условия — `tools/verify/README.md`, пороги — `tools/verify/criteria.default.json`)
| # | требование заказчика | артефакт (инструмент) | правило вердикта (по умолчанию) |
|---|---|---|---|
| V1 | основные веса ≥ 4 бит качества | `tools/gguf_quant_audit.py --json` (без `--dense-warn-only`) | PASS, если ни одного типа < 4.0 bpw ни в экспертах, ни в остальных матрицах (сборщик перепроверяет гистограммы типов сам), нет неизвестных типов; иначе FAIL. Не-GGUF формат — NOT RUN (инструмента нет) |
| V2 | целостность весов | манифест `scripts/offline/weights.py manifest` **и** вывод `weights.py verify` | PASS, если каждый файл манифеста проверен с тем же sha256 и размером, ревизия — 40-hex коммит |
| V3 | ≥ 262 144 реально используемых токенов | `tools/bench/probes.py` на 262K | needle ≥ 0.8, multihop ≥ 0.75, code-QA ≥ 0.75 на контексте ≥ 262 144, сервер не обрезал промпт; каждый запрос на полное окно выдал непустой вывод; `tools` и `json` = 1.0 |
| V4 | декод single-stream ≥ 50 tok/s при заполненном контексте | `tools/bench/run_matrix.py` | в каждой single-stream ячейке «при заполненном контексте» (ниже) с выводом ≥ 512: 0 отказов, ≥ 3 повтора, p50 ≥ 50 → PASS (≥ 80 — отдельный необязательный критерий «цель»); < 50 → FAIL; нет такой ячейки → NOT RUN |
| V5 | кэш префиксов работает | `run_matrix.py` cold/warm и `--scenarios agent` | на заполненном контексте TTFT warm p50 ≤ 10% cold p50, сервер сообщает `cached_tokens` > 0; agent loop без отказов до ≥ 100 000 токенов промпта |
| V6 | точная маршрутизация | `tools/quality/logprob_compare.py`: эталон — llama.cpp на **тех же** весах со всеми экспертами | ≥ 200 префиксов без ошибок, top-1 ≥ 0.97 (PROVISIONAL, не откалибровано: заменить измеренным шумом «тот же GGUF, CPU против GPU» в llama.cpp); расхождение top-1 у почти-ничьей (`ref_gap + cand_gap` ≤ 0.025 нат, PROVISIONAL, N24: `docs/evidence/2026-10-11-n24-owner-decisions.md` раздел 2) считается совпадением; для сравнения: ADR-012 D4 — 0.9 для «сопоставимого качества», D1 — 0.99 для патча кэша |
| V7 | сохранение/восстановление состояния | `tools/kv/slot_persist.py` (K3) | ≥ 3 повтора без ошибок, продолжение совпадает, восстановление + тёплый префилл ≤ 25% холодного. Ошибки в артефакте → FAIL (по артефакту нельзя отличить «у движка нет функции» от «забыли флаг»). Обязательный по умолчанию; если по K3 сохранение не окупается или движок его не умеет, заказчик может исключить V7 — сборщик тогда помечает вердикт как «НЕ по исходным требованиям» |
| V8 | факты о железе измерены | `scripts/diag/summarize.py --json` | `synthetic` = false, измерены число GPU (= 4), PCIe, AVX2/AVX-512, каналы и полоса RAM, P2P, H2D, fio. Совпадение hostname и красные флаги — только в деталях |
| V9 | замер против границы | `tools/bench/vs_roofline.py --json` | файл обязателен, строка на каждую ячейку заполненного контекста; само отношение информационное. Отношение > 1 → NOT RUN (`invalid`: входы границы неверны), не FAIL |

| V11 | качество на задачах заказчика | `R2-EVAL-SET.md`, отчёт R2.2 | ручной; автоматически не проверяется |

**Заполненный контекст (решение ведущего, PROVISIONAL).** По умолчанию ячейка считается снятой при заполненном контексте, если
промпт + вывод ≥ 262 144 − 16 по измеренному серверу `usage` и вывод ≥ 512 (`decode_filled_context_basis: "prompt_plus_output"`) —
так требование сформулировано в `EXPERIMENTS.md` («промпт ≥ 262 144 − N, затем вывод N»). Строгое прочтение «промпт сам ≥ 262 144»
включается `"prompt"`; модель с нативным окном ровно 262 144 (Qwen3.8-Flash-Next) его без YaRN не пройдёт (`BRINGUP-qwen38fn.md`,
«Окно контекста»). Какое прочтение принимать для сдачи — решает заказчик.

Сквозные правила вердикта (реализованы в сборщике и покрыты тестами — см. `tools/verify/README.md`):
- отсутствующий, нечитаемый или внутренне противоречивый артефакт (`summary.json` не совпадает с пересчётом из `raw.jsonl`) →
  NOT RUN, никогда не PASS;
- артефакт, снятый против mock-сервера (`tools/bench/mock_server.py`: `owned_by: 408032gb-bench-mock`, `is_mock_server: true`,
  плашка «MOCK SERVER RUN»), → NOT RUN с причиной «mock»; так же — выводы `logprob_compare`/`slot_persist` с URL mock-прогона;
- скорость декода берётся только из ячеек заполненного контекста;
- общий PASS — только если все обязательные критерии PASS и каждый артефакт разобран; любые отличия порогов от умолчаний
  выносятся плашкой в `VERDICT.md`.

Проверка самого сборщика: 19 тестов на артефактах, которые делают сами инструменты (в том числе на mock-сервере), и 10/10
одноточечных мутаций `pack.py` пойманы — литерально в `docs/evidence/2026-10-09-tool-mutations.md`, раздел «tools/verify/pack.py».

## Состав каталога pack
```
verification-pack-<date>/
  VERDICT.md            таблица V1–V11: PASS / FAIL / NOT RUN, значение, путь к артефакту (по-русски)
  verdict.json          то же для машин
  MANIFEST.sha256       sha256 каждого файла pack (проверка: scripts/verify_pack.sh --check <dir>)
  env.txt               git rev-parse HEAD, git status --short, uname -a, python3 --version, nvidia-smi -L
  criteria.json         действующие пороги
  artifacts/            копии входных артефактов: quant-audit, weights-verify, bench run dirs, probes, logprob, slot_persist,
                        vs_roofline, diag summary
```

## Как собрать (на сервере после R1–R5)
```
scripts/verify_pack.sh --runs <каталог с выходами инструментов> --out docs/evidence/verification-pack-<date>
scripts/verify_pack.sh --check docs/evidence/verification-pack-<date>
```
Точные флаги — `python3 tools/verify/pack.py --help` и `tools/verify/README.md` (README — источник истины). Pack коммитится в
репозиторий (кроме весов и больших трасс — для них в pack только sha256 и путь) и передаётся бандлом.

## Чего pack не доказывает
- Качество на задачах заказчика вне оценочного набора R2 (V11 — выборка, а не гарантия).
- Устойчивость под нагрузкой дольше прогона soak.
- Поведение на другой версии движка/драйвера: pack привязан к `env.txt`.
