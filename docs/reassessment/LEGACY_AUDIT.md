## ADR-001. Порядок моделей GLM → MiMo → DeepSeek — REVALIDATE

- **Почему было разумно тогда.** Strata (Qwen3.8-Flash-Next) и GLM-5.3-Flash делят строители графа llama.cpp (GDN/KDA, k-pool
  индексер, hyper-connections) — CONFIRMED по `src/models/qwen4exp.cpp` и `glm5-next.cpp`; перенос дешевле всего.
- **Почему может быть неверно сейчас.** (1) Критерий выбора — удобство порта, а не качество для code-agents, 262K и скорость.
  (2) Не сравнивались модели, целиком помещающиеся в 128 GB VRAM в 4-бит с KV на 262K: только они дают шанс на 80–100 tok/s
  (физика: при пропускной ≈ 700 ГБ/с на карту токен, требующий 5–10 ГБ чтения, ограничен 70–140 tok/s даже без промахов; любой
  выход экспертов в RAM на 100–200 ГБ/с снижает потолок кратно — PROVISIONAL, см. roofline). (3) DeepSeek-V4.1 предполагал переквант
  ≤3 бит (конфликт C4).
- **Подтверждения.** Геометрия GLM — CONFIRMED (HF config 2026-10-01); качество моделей между собой в репозитории не сравнивалось вовсе.
- **Альтернативы.** Модели среднего размера (полностью в VRAM) против больших с ярусами; другой первый кандидат по Pareto.
- **Цена ошибочного сохранения.** Недели работы над движком для модели, которая либо не даёт 50+ tok/s на 262K, либо уступает по
  качеству альтернативе.

## ADR-002. Новый backend рядом с qwen4exp внутри Strata — SUPERSEDE

- **Тогда.** Strata однопородный (CONFIRMED: guard `qwen4exp`, константы геометрии), параметризация всего движка дорога.
- **Сейчас.** Для GLM уже заменён ADR-007; для MiMo/DeepSeek держится на допущении «основа — Strata», которое мастер-промпт снимает.
  Мысль «геометрия экспертов — параметр времени выполнения» верна для любого собственного рантайма и переходит в дизайн, если
  выбран путь D/E.
- **Цена сохранения.** Привязка к однопородному движку, отставшему от апстрима.

## ADR-003. Сначала конвейер по слоям, TP/EP — потом — REVALIDATE

- **Тогда.** Конвейер уже есть в Strata, бит-экзактен, P2P не требует — правильный первый шаг для корректности.
- **Сейчас.** При одном потоке декода конвейер нагружает одну карту в каждый момент: потолок ≈ полоса одной карты (ADR сам это
  признаёт). Для MoE при batch=1 есть третий вариант — **экспертный параллелизм внутри слоя** (эксперты слоя разнесены по 4 картам,
  все 4 читают свои эксперты одновременно; между картами ходит только вектор скрытого состояния ~8–64 КБ) — HYPOTHESIS: выигрыш до
  ~4× на экспертной части при цене ~2 синхронизаций на слой; работает и через pinned host без P2P, но латентность PCIe на 42+ слоях
  может съесть выигрыш. Решается замером на сервере.
- **Цена сохранения.** Потолок single-stream, заниженный в 2–4 раза относительно возможного.

## ADR-004. CPU-путь только AVX2 — KEEP (до CPUID)

- EPYC 7H43 = Zen 3 (Milan) без AVX-512 — паспортный факт (подтверждается в `research/R4-hardware.md`); на сервере проверить `lscpu`.
- Сохраняется; уточнение: кроме i-quant нужны AVX2-ядра Q4_K/IQ4_XS для CPU-экспертов (в llama.cpp/ik_llama они есть).

## ADR-005. Ярусность покупает качество — KEEP принцип, SUPERSEDE вариант IQ2/IQ3

- **Тогда.** Выбор между «IQ3 почти весь в VRAM» и «Q4 с ярусами» оставлялся замеру G5.
- **Сейчас.** Заказчик требует ≥ качественного 4-бит для основных весов; IQ2/IQ3 допустимы только как отдельный экспериментальный
  режим с измеренным штрафом. Принцип «RAM/NVMe-ярусы ради 4-бит качества» совпадает с новым требованием.

## ADR-006. Разработка без GPU — SUPERSEDE частично

- **Тогда.** Сервер был недоступен, у заказчика только телефон.
- **Сейчас.** Заказчик готов к работе с физической машиной (BIOS, фото, диагностика). CPU-first разработка корректности (оракулы,
  крошечные модели, CI) остаётся (KEEP), но запрет «числа скорости до сервера не публикуются» сменяется планом немедленных замеров на
  сервере. Kaggle/Colab T4 (sm_75) для корректности CUDA — второстепенно, если сервер доступен.

## ADR-007. База A = sergqwer/strata-glm (NVFP4, ярусы) — REVALIDATE

- **Тогда.** Готовый GLM-движок с ярусами VRAM/RAM/диск; ядра собираются под sm_89 (CONFIRMED); автор заявлял 16.5–18 tok/s на одной
  5090 (PROVISIONAL).
- **Сейчас (риски).** (1) ADR называет репозиторий архивным; на GitHub он archived не помечен (REPORTED, R2), но апстрим-поддержки
  под наши задачи нет: последние изменения — в форке strata-glm-3090. (2) Одна модель, один GPU, NVFP4-чекпойнт
  204 GB; на sm_89 FP4 декодируется программно (нет FP4 tensor cores) — для GEMV это близко к норме по памяти, для prefill-GEMM
  проигрыш (PROVISIONAL). (3) Нет OpenAI-сервера, кэша префиксов, батчинга (проверяется в R2). (4) Все запуски в нашем репозитории —
  синтетика; на реальных весах есть чужой замер форка strata-glm-3090: 6.85 → 13.89 tok/s с `--cpu-share`, повтор эксперта 24.6%
  (REPORTED, `research/R2-engines.md` §3.4) — это единственное подтверждение политики «промахи считает CPU» (D7) на реальных весах.
- **Ценность.** Донор дизайна ярусов (O_DIRECT DiskReader, TieredExpertSource, разбиение по слоям, профиль горячих экспертов).
- **Цена сохранения как основы.** Собственная поддержка форка движка без апстрим-поддержки, без сервера и без prefix-кэша.
- **Решение (ADR-012 ред. 2).** Не основа, но строка бейзлайн-матрицы R1.5 для GLM: сборка sm_89 уже есть в CI; разморозка — по
  проверяемому условию D4.

## ADR-008. DeepSeek-V4.1-Flash: CPU-трек и два эталона — KEEP метод, REVALIDATE приоритет

- Метод (граф llama.cpp для общих с V4 операций, референс DeepSeek для новых; подмена ядра с режимами «как в референсе»/«точно»)
  — образцовый, KEEP. Находка A (decode не воспроизводит prefill в референсе) — ценная, KEEP как факт.
- Приоритет модели решается R1: эксперты MXFP4 275.7 GiB + Engram 188.8 GiB (PROVISIONAL, fitplan) требуют NVMe-яруса для ~48 GiB
  экспертов при 4-бит; при равномерной маршрутизации это промахи на SSD каждый токен.

## ADR-009. База B = lighttransport/Strata glm53f (GGUF) — REVALIDATE

- **Тогда.** Публичный форк с нативным GGUF-бэкендом GLM; ТЗ заказчика требовало GGUF внутри Strata.
- **Сейчас.** Автор сам пишет, что сквозного совпадения с llama.cpp нет (отн. L1 0.059, max |Δlogit| 0.84 — CONFIRMED по тексту
  автора); один GPU; нет prefix reuse, батчинга, tool-call; нет Q4_K-экспертов; 253 коммита позади апстрима Strata; GGUF-диалект
  несовместим с нашим эталоном. Числа автора — 7.3–8.4 tok/s на 5060 Ti + CPU-экспертах.
- **Цена сохранения как основы.** Мы берём на себя parity, многокарточность, Q4-ядра, сервер и кэш — по сути пишем движок заново
  поверх чужого кода без апстрим-поддержки.

## ADR-010. Веса GGUF `glm5next`, UD-Q2_K_XL первым — SUPERSEDE п. 2–3, KEEP п. 4, REVALIDATE п. 1 и 5

- п. 2 «первая очередь Q2» — конфликт C3 с требованием ≥4-бит: **SUPERSEDE**. Q2 допускается только как отладочный режим проверки
  корректности при нехватке памяти, с явной меткой, никогда как поставляемый.
- п. 3 «UD-Q4_K_XL как ярус качества» — становится основным вариантом для GLM, если GLM останется (REVALIDATE вместе с ADR-001).
- п. 4 «не делать GGUF→pack (двойное квантование)» — **KEEP**: двойное квантование ухудшает качество без нужды.
- п. 1, 5 (формат GGUF, база A запасная) — REVALIDATE после выбора движка (форматы 4-бит: GGUF Q4_K/IQ4_XS, AWQ/GPTQ-INT4,
  NVFP4/MXFP4 — R1/R3).

## ADR-011. DFlash2 на базе B после parity — REVALIDATE (правило автоотключения — KEEP)

- Правило «спекуляция включается только где свой замер показывает выигрыш, иначе автоматически отключается» — KEEP для всех видов
  спекуляции.
- Привязка к базе B — REVALIDATE. Риски, записанные в ADR (рост трафика экспертов при проверке блока; драфтер обучен на W4A16) —
  остаются гипотезами для эксперимента. Для агентных code-задач дешёвый кандидат — n-gram/suffix-спекуляция (R3).
- Оракул `ref/dflash2.py` и его evidence (`docs/evidence/2026-10-03-dflash2-oracle.md`) — **KEEP** (исправлено после ревью, п. 19):
  llama.cpp и ik_llama уже исполняют DFlash/DFlash2 (`research/R2-engines.md`), оракул пригоден для проверки их реализации в S3.
  Заморожен только собственный движок DFlash2 на базе B.

## ТЗ «GLM-5.3-Flash для Strata» (`docs/prompts/GLM53-TZ.md`) — SUPERSEDE как рамка, KEEP принципы

KEEP (это хорошие инженерные правила для любого движка): корректные логиты и тесты против эталона, а не «загрузилось»; совпадение
не только по top-1 (max/mean abs, cosine, top-k overlap); prefill(N)+decode(1) = prefill(N+1); обратимый откат кэша при спекуляции;
явные предупреждения о fallback; бенчмарк до/после для каждой оптимизации; MTP и DFlash2 в разных путях исполнения.
SUPERSEDE: обязательность Strata, GLM как единственной цели, AMD HIP/Vulkan, порядок «Q2 сначала».
