# G8: DFlash2 для GLM-5.3-Flash на базе B (дизайн, ADR-011)

Статус: дизайн. Ни одна строка движка не написана; ни одной цифры скорости нет. Факты об алгоритме —
`docs/models/glm-5.3-flash-dflash2.md`.

## Что должен дать движок цели
1. **Отводы скрытых состояний.** После слоёв из `target_layer_ids` (у вендорского драфтера 5, 14, 24, 33, 42 — PROVISIONAL)
   сохранять скрытое состояние каждого принятого токена. В GLM поток несёт mHC: какой именно тензор отводится (свёрнутый поток
   или один из четырёх) — взять из `vllm/models/glm5next` на пине, не угадывать. UNKNOWN до чтения.
2. **Проверка блоком.** Один проход цели по 8 позициям (якорь + 7 черновых). В базе B такой проход уже есть для MTP и
   prompt-lookup (`--check-verify`); DFlash2 подаёт в него свои токены.
3. **Откат и фиксация.** Снимок состояния KDA, кэшей DSA и пулов индексера до проверки, откат непринятого хвоста. В базе B
   есть snapshot/replay; для DFlash2 добавляется откат KV самого драфтера.

## Драфтер как отдельная маленькая модель на GPU
- Контекст: `fc(concat отводов)` → RMSNorm → проекции K и V каждого слоя драфтера → RMSNorm по K → RoPE → KV-кэш драфтера.
  Слои драфтера по контексту не исполняются, это одна матричная операция на принятый токен.
- Блок: вход — якорный токен и 7 масок; проход по слоям драфтера (внимание на KV контекста в окне 2048 и на позиции блока,
  групповая свёртка до и после внимания и MLP); финальная норма; общая с целью выходная голова.
- Селектор: top-16 кандидатов на позицию, оценка рёбер по кодовым книгам ранга 256, обход от якоря — 7 токенов.
- Память: около 2.2 GiB весов (bf16, PROVISIONAL) плюс KV на окно 2048 для 5 слоёв. На сервере помещается на любую карту.

## Цикл одного шага
1. цель выдала токен t и отводы для него → обновить KV драфтера;
2. драфтер выдаёт 7 токенов;
3. снимок состояния цели; проход цели по [t, d1..d7];
4. принять самый длинный совпавший префикс (жадный режим), откатить остальное, обновить KV драфтера по принятым;
5. счётчики: предложено, принято, длина принятия, время драфтера, время проверки.

## Где выигрыш возможен, а где нет
- Проверка 8 позиций обращается к экспертам до 8 раз чаще, чем обычный шаг. Если эксперты в VRAM, это один батч на GPU.
  Если часть экспертов в RAM или на CPU, трафик растёт пропорционально — поэтому целевая конфигурация для DFlash2:
  «все эксперты в VRAM» (ADR-010, UD-Q2_K_XL). Для UD-Q4_K_XL с ярусом в RAM выигрыш не предполагается, только замер.
- Доля принятия зависит от того, насколько отводы квантованной цели близки к тем, на которых учили драфтер. Для Q2 — UNKNOWN.
- MTP уже есть в базе B: DFlash2 принимается, только если на одном и том же прогоне он быстрее MTP и обычного декода.
